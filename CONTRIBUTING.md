# Contributing to shadcn-qt

shadcn-qt uses a GPLv3/commercial licensing model. To preserve the project's
ability to offer the same code under both licenses, every non-trivial external
contribution needs an accepted Contributor License Agreement (CLA).

## Before opening a pull request

1. Open an issue describing the change.
2. Keep generated files in sync by running
   `python tools/token-codegen/generate.py` when tokens change.
3. Run the Python tests and documentation build described in the README.
4. Read [CLA.md](CLA.md). The pull request must record the contributor's
   acceptance using the exact statement below, with the contributor's legal
   name and date:

   `I have read and agree to the shadcn-qt CLA v1.0: NAME, YYYY-MM-DD`

A maintainer must verify and retain that record before merging. Contributions
from an employer should also include confirmation that the contributor has
authority to grant the CLA rights. Typo-only or similarly non-copyrightable
changes may be accepted without a CLA at the maintainer's discretion.

Do not submit code copied from another project unless its license and
provenance have been reviewed and recorded. In particular, visual inspiration
or API semantics do not make third-party source code safe to copy.
